Add Apple property lists to the formats yq can read and write. Two names should be available wherever the existing formats are: plist for the XML flavour and bplist for the binary one, both usable for input and for output, and a file whose name ends in .plist should be recognised as a property list on its own.

On input either name should accept whichever flavour it is handed, since a file on disk may hold either. A property list carries exactly one value, so a second read reports end of input. Dictionaries become maps and arrays become sequences. Strings, integers and reals become the matching scalars, true and false become booleans, a data element becomes a !!binary scalar holding its base64 text, and a date becomes a !!timestamp, with dates taken from the binary flavour rendered as RFC 3339 in UTC. The XML flavour may arrive with or without its enclosing plist element. Anything that is not a well formed property list has to be reported instead of guessed at: a dictionary entry missing its key or its value, an element that means nothing here or that is nested where only text belongs, a numeric element holding something that is not a number, more than one root value, or a binary document whose header, root reference or offset table does not line up.

Writing plist should produce a whole XML document laid out the way Apple's own tools write one: the XML declaration, the standard PLIST 1.0 document type declaration, a plist element at version 1.0, the root value at the left margin with one tab of indentation for each level below it, empty dictionaries and arrays as self-closing elements, and text escaped as XML requires. Writing bplist should produce a binary document that yq reads back unchanged. Property lists have no null, so writing one has to fail rather than invent a stand-in.
