Add Apple property lists to the formats yq can read and write. Two names should be available: plist for the XML flavour and bplist for the binary one, and a file whose name ends in .plist should be recognised as a property list.

On input either name should accept whichever flavour it is handed, since a file on disk may hold either. A property list carries exactly one value, so a second read reports end of input. A data element becomes a !!binary scalar holding its base64 text, and a date becomes a !!timestamp, with dates taken from the binary flavour rendered as RFC 3339 in UTC. The XML flavour may arrive with or without its enclosing plist element. Anything that is not a well formed property list has to be reported instead of guessed at, whether the document is malformed XML, structurally invalid, or a binary document whose header, root reference or offset table does not line up.

Writing plist should produce a whole XML document laid out the way Apple's own tools write one: the XML declaration, the standard PLIST 1.0 document type declaration, a plist element at version 1.0, dictionary entries in the order they are held rather than sorted, the root value at the left margin with one tab of indentation for each level below it, and empty dictionaries and arrays as self-closing elements. Writing bplist should produce a binary document that yq reads back with the same values. Property lists have no null, so writing one has to fail rather than invent a stand-in.
